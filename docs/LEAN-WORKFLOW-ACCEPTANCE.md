# Codex 轻量治理阶段验收 — 2026-09-28

状态：开发候选通过本阶段验收；不是已安装版本，也不是稳定版性能承诺。

## 保留与改变

- 健康默认/Light 任务入口安静运行；恢复、doctor 和历史读取按实际需要触发。
- 决策、快照目录中的普通 Markdown 记录变化只产生恢复提醒。它不批准新决定，
  不更新激活基线，也不要求只为项目笔记重新激活。
- Constitution、AGENTS、scope、实际策略文件、缺失目录和不安全目录项仍保留边界。
- 未完成验证继续保留；普通项目记录不创建新的 Stop 义务。
- 删除放行例外已经撤回。没有增加全局 warning-only 模式、第二套 Gate 或数据库。
- Guardian 保持独立；根据真实临时会话日志验证并支持 CLI 0.158.0-alpha.2.1。

| 跨任务验证义务 | 回归检查确认恢复时提醒、原义务保留，基线未自动改变 | 安静入口和项目笔记不会清除义务 |

原生测试使用独立临时 CODEX_HOME、本地固定响应和临时文件，无真实模型/账户调用。
仅对这些已审阅的临时 Hooks 使用调用级 trust bypass；原生 sandbox/approval 保留。
这不是桌面用户 Hook 信任验收，也不是 Astra 自主语义恢复或长期生产可靠性证明。

首轮原生测试有三个升级断言失败：测试没有等待命令完成且登录 shell 可选择旧 CLI。
第二轮显式源码路径又受现有窄命令语法限制。最终使用非登录 shell 保留临时 PATH，
明确运行候选 CLI，并等待固定检查完成。没有放宽生产 Gate 或平台权限来通过测试。
原始失败结果与最终结果均保存在本地实验目录；未把它们混成全部通过。

## 成本与复杂度边界

同一健康入口 fixture 的上下文注入曾从 762 字符降到 0，事件读取从 2 次降到 1 次。
此前真实短任务 Quiet/Clean 样本数量小、耗时与 token 结果混合；本阶段没有重跑模型
benchmark，也没有宣称稳定整体提速。Hooks 的完整性检查和本机账本仍有运行成本。
Markdown 记录提醒只在入口/恢复时出现，不在每次普通工具调用时重复。

## 发行和安装交接

本阶段可停止继续开发。当前公开安装配方仍指向不可变 v0.3.0-rc.1，不能用本候选
覆盖旧标签，也不能把源码推送当成安装生效。后续发行安装需要：

1. 确定新候选版本，更新版本标识、已安装 0.3.0-rc.1 的精确升级来源与摘要。
2. 验证公开包和真实安装/升级流程，核对 CLI 来源，保留既有项目记录和本机账本。
3. 安装完成后重启桌面并由用户审阅新的 Hooks；再验证实际加载版本与首个 Hook。

在此之前不要承诺日常任务已运行新逻辑。任意未知 CLI 版本仍不在 Guardian 支持范围。
